### What the tests actually cover

| Area | Examples |
| --- | --- |
| Anchored boundaries | 09:03:20 start → 09:18:20/09:33:20 boundaries; a save never shifts them; 48 requests end at the 12-hour cap |
| Gaps and prompts | 10:00–10:45 missed at 10:50 → one 45-minute completed proposal, 10:45–10:50 stays current; Log Now 10:15–10:22 saves exactly 7 minutes |
| Balance identity | `recorded + skipped + unresolved = elapsed` after create/skip/delete/edit, two sessions, midnight crossing, DST day, and the 12-hour cutoff |
| Storage | migration idempotence, newer-schema refusal, foreign keys, one-active-session index, entry text/range constraints, unique action ID |
| Transactions | duplicate Save returns one row, competing action IDs produce one winner and a typed conflict, stale revision/deletion rejected without partial mutation |
| Reminders | 48 future boundaries scheduled once, lost metadata does not duplicate OS requests, permission denial/restore, reminders off cancels, Stop cancels and dismisses, expired session closes at the cutoff, orphan cleanup, backward-clock review |
| Read models | Today targets/totals, History day rows, midnight clipping, 120-day fixture without precomputed totals |
| Offline journey | start → consolidated gap → partial Log Now (7 min) → Continue → Skip → edit → delete → Stop, asserting the balance identity and non-overlap after every mutation |
| Stop future guard | `stopSession` rejects an end after `now` (`SESSION_END_IN_FUTURE`) and accepts an end exactly at `now` |
| Stale payload versions | reconciliation cancels pending requests from older payload versions, for the active session, a foreign session, and with no session at all; Stop also cancels older-version requests for its session |

## Physical-device E2E script: BLOCKED

No device is attached. The checklist from
[e2e-spec §8.3](../e2e-spec.md#83-physical-device-e2e-script) to execute when
one is available:

- [ ] Install the candidate on the Samsung; start with internet off.
- [ ] Grant permission, press Start at a known timestamp.
- [ ] Lock the phone; record planned vs actual first alert; tap from locked and
      terminated states and save a description.
- [ ] Continue previous at the next prompt; verify distinct contiguous entries.
- [ ] Ignore two prompts; reopen; record one consolidated completed gap that
      excludes the current partial interval.
- [ ] Use Log Now before a boundary, then save another activity; verify no
      rounding and no overlap.
- [ ] Skip, delete and edit; check `recorded + skipped + unresolved = elapsed`
      after each mutation.
- [ ] Stop; verify no intended future prompts and that a stale tap only opens
      historical unresolved time.
- [ ] Kill/reopen and reboot/reopen; confirm history and session state persist.
- [ ] Deny permission, re-enable; confirm manual logging works throughout.
- [ ] Verify no requests are scheduled beyond the 12-hour cap.
- [ ] Record device model, Android version, app version, battery setting,
      planned/actual times, missed alerts, and UI friction.

## Accessibility and honesty checks (code-level, not device-verified)

- Touch targets ≥ 48 px for primary and secondary actions; chips ≥ 40 px.
- Buttons/rows expose `accessibilityRole`, labels and hints; the timeline
  announces time ranges, kind and duration; the countdown has a text label.
- Colors are backed by text (Recorded/Skipped/Unresolved labels, dot + text),
  never color alone; font scaling is allowed up to 1.6×.
- No screenshot text, sample date, or mock totals are rendered: all values come
  from `getToday`/`getDayDetail`/`getHistory` over SQLite.
- Empty, idle, denied, unresolved, skipped, expired and storage-error states
  are rendered from real state; `expo export` produced no warnings for them.
